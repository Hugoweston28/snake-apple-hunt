# 贪吃蛇吃豆 · 100×100

蛇在 100×100 的空地上吃光 10 个苹果，用最少步数。考核点是「程序怎么自己找最短路线」，所以核心不是把蛇写出来，而是把**最短性**证出来。

当前进度：**三批全部完成**（引擎 / 最优解 / 验证器 / 跑分 / 页面 / 渲染 / 回放 / 四套皮肤 / 人类可玩）。

---

## 怎么打开

**在线直接玩：<https://hugoweston28.github.io/snake-apple-hunt/>**（GitHub Pages，手机和电脑都能开）

本地离线玩：**双击 `启动游戏.cmd`**。它会起一个本地静态服务器并自动打开浏览器（`http://127.0.0.1:8123/`），关掉那个黑窗口即停止服务。

> ⚠️ **不要直接双击 `index.html` / `dist/snake.html`**。
> 部分环境（安全软件、浏览器策略、企业管控）会拦截 `file://` 下执行的脚本，
> 表现就是「页面框架在、但棋盘全黑、按钮全没用」。这不是代码问题，是协议限制。
> 用 http 打开就正常。

也可以手动起服务：

```bash
node tools/serve.js          # 8123 端口
node tools/serve.js 8080     # 指定端口
node tools/serve.js --open   # 起服务并打开浏览器
```

GitHub Pages 已经部署好了。仓库根目录就是可部署产物（`index.html`），改完源码 `node build.js`
重建后提交即可，Pages 会自动更新。

改源码时改 `template.html` 和 `js/*.js`，然后：

```bash
node build.js            # 重新生成 index.html 与 dist/snake.html
node tools/smoke_dom.js  # 无浏览器时用 DOM 桩跑一遍，抓运行时错误
```

> `template.html` 是开发模板（ES Module），**必须**通过 http 访问，双击一定白屏。

## 界面

- 左：棋盘（Canvas）。右：数据面板 + 控件。
- **两种模式**：`AI 自动`（看 AI 怎么走） / `我来玩`（键盘控制）。
- **回放器**（AI 模式）：播放 / 暂停 / 单步 / 上一帧 / 重播 / 换一局、进度条拖拽、7 档倍速（0.5×–32×）。整局先算完再逐帧回放，所以拖动进度条是瞬时的。
- **AI 计划路线**：棋盘上叠加当前决策的虚线路径 + 目标苹果的圈，可开关。人类模式下这条线是**从你当前位置重新算的**，不是 AI 自己的那局。
- **四套皮肤**：霓虹 / 经典绿 / 彩虹 / 熊猫 emoji，切换不重置对局、不影响步数。
- 快捷键：`空格` 播放暂停、`←/→` 单帧（AI 模式）、`R` 重播。

### 人类可玩

方向键 / WASD 控制，空格暂停。三个设计上的要点：

1. **转向输入缓冲队列（上限 2）**。不做的话，16ms 内连按两个方向会丢输入，玩家会被迫走反方向撞自己——这是最劝退的体验 bug。
2. **禁止 180° 反向**：按反方向直接忽略，不惩罚（也判断队尾方向，避免"先右后左"这种自相矛盾的入队）。
3. **实时对照**：HUD 里的「最佳可达」= 当前步数 + 从你当前位置出发的剩余最优步数。它不是固定的下界，是**你现在还来得及做到的最好成绩**；一旦你走偏，这个数就会大于「理论最优」，立刻可见。

撞死后不弹窗，直接在面板里给出：第几步、撞什么、该 seed 的理论最优步数。

### 手机 / 触屏：滑动转向

手机上放不了方向键——拇指一按就盖住棋盘的一大块。改成**整块棋盘当摇杆**：

- 手指按在棋盘**任意位置**即为锚点，不必找按钮。
- 相对锚点滑动超过 24px，取主轴方向发一次转向，**锚点随即移到当前点**，所以不抬手就能连续转向（上→右→下…），正好喂满上面那个长度为 2 的缓冲队列。
- 特效：沿手指轨迹的划痕光带（深色皮肤用 `lighter` 叠加，浅色皮肤用普通叠加，否则熊猫白底会被洗白）+ 指尖光点 + 每次真正转向处炸开的小涟漪和方向切口。转向有没有被吃进去，看涟漪就知道。
- 游戏暂停时滑动会自动恢复——手机上的暂停按钮在棋盘下方，不在视野里。

实现：`js/touch.js`（`TouchSteer`），叠加层是 `.board-wrap` 里的 `#fx` canvas，`pointer-events: none`，`touch-action: none` 防止滑动时页面跟着滚。

### 可分享的对局

URL hash 直接定位到某一局某一帧，便于复核和发链接：

```
dist/snake.html#seed=7&frame=260&skin=panda
dist/snake.html#seed=3&algo=greedy&skin=rainbow
dist/snake.html#mode=human&seed=7&keys=RURDLLURD...&frame=200
```

参数：`seed` / `algo`(`optimal|greedy|random`) / `frame` / `skin` / `plan=0` / `mode=human` / `keys=URDL串` / `apples` / `snake`。

`keys` 是人类局的**按键序列**。一局打完点「复制复核链接」，得到的就是它——任何人打开都能逐帧重演你的操作，验算步数。撞墙成绩无效这条规则，由此变成可程序化复核的东西，而不是靠人盯着看。

### 渲染上的两条硬规则

1. **蛇身必须是连续的胶囊链**，不是一格一个圆角方块——后者会变成一串珠子，头粗尾细的锥形也立不住。
2. **网格按格宽分级**：格宽 < 9px 只画每 10 格的辅助线。100×100 铺到 800px 时格宽只有 8px，画满 100 条线会退化成摩尔纹噪点（经典绿那套尤其明显，已修）。

## 规则（与题目对齐）

| 项 | 取值 |
|---|---|
| 地图 | 100×100，坐标 0..99 全部可走，越界即撞墙 |
| 蛇 | 初始长 3，位置与朝向随机 |
| 苹果 | 10 个，互不重叠、不落在蛇身上 |
| 计步 | 每移动 1 格 +1 |
| 吃苹果 | 该步尾巴不动，蛇长 +1，苹果数 −1 |
| 判定顺序 | 先算新头 → 判越界 → 判是否落在「移动后的身体」上 → 合法才提交 |
| 结束 | 撞墙/撞身 = 本局无效；吃完 10 个 = 通关 |

## 核心结论：最优步数是可精确计算的

设蛇头 $h$、苹果集合 $A$、$d$ 为曼哈顿距离。

**下界.** 任何一条吃完所有苹果的路径，按「首次到达每个苹果的时刻」排序得到访问序 $\pi$。相邻两次首到之间的实际步数 $\ge$ 两地曼哈顿距离，故
$$\text{总步数} \ge d(h,a_{\pi_1}) + \sum_i d(a_{\pi_i},a_{\pi_{i+1}}) \ge \min_{\pi}(\cdot)$$

**可达.** 对取到最小值的 $\pi$，逐段走曼哈顿最短路拼接，步数恰好等于该下界（顺路经过的苹果会被免费吃掉，L1 的三角等式保证不会算多）。

所以「理论最少步数」= 在 10 个苹果上做一次路径版 TSP，用 Held-Karp 动态规划 $O(2^n n^2)$ 精确求解。n=10 约 10 万次运算，**毫秒级**。界面上「理论最优」那一栏就是它，`差距 = 实走 − 理论最优`。

## 实测结果（1000 局，seed 1..1000）

| 算法 | 通关 | 平均步数 | 与下界差距（均值 / 最大） | 耗时 |
|---|---|---|---|---|
| **最优（Held-Karp）** | 1000/1000 | 306.8 | **0.184 / 4** | 3.7s |
| 贪心最近邻 | 1000/1000 | 336.1 | 29.50 / 152 | 1.6s |
| 随机游走 | 0/1000 | — | — | 3.1s |

- 重演校验 **1000 局 0 失败**
- **91.3%** 的局数步数**恰好等于理论下界**，99.5% 在 +2 步以内
- 贪心比最优平均多走 29.3 步（**+9.6%**）

### 避身：从"时间无关"改成"时间相关"

第一版的 BFS 把蛇身当成静态墙，所以头必须绕开一整条身体。但身体是**每走一步往后缩一格**的：

> 蛇身第 $k$ 节（0 = 头）在 $t$ 步后已被挤到第 $k+t$ 节，身体共 $L$ 节，
> 所以它在 $t \ge L-k$ 时才让开。于是「第 $t$ 步能否进入格 $c$」$\iff t \ge \text{freeTime}(c)$。

把这条塞进 BFS（按时间分层推进，每个格子只在"已经让开"之后才允许进入），头就能直接追着自己的尾巴走，不用绕圈。

| 指标 | 时间无关 BFS | 时间相关 BFS |
|---|---|---|
| 平均差距 | 0.318 | **0.184** |
| 最大差距 | 16 | **4** |
| 恰好达到下界 | 86.8% | **91.3%** |
| 差距分布 | +0:868 +2:117 +4:12 +10:2 +16:1 | **+0:913 +2:82 +4:5** |

`+10` 和 `+16` 那种绕一整圈的情况彻底消失了。事前我估的是能推到 95% 以上，实际到 91.3%——剩下的是真补不掉的（见下）。

### 剩下的 8.7% 是什么

不是 bug，是物理约束：**在到达那一刻，那格确实还被自己的脖子占着**，只能绕 2 步。归因脚本显示这些 +2 分散在各段，不是集中在开局。

### 差距恒为偶数

网格是二分图，每走一步翻转颜色，所以总步数的奇偶性被起点与终点固定死；曼哈顿距离和同样如此。于是 `实测 − 下界` 必然是偶数。实测分布 `+0:913 +2:82 +4:5` 全部是偶数，反向印证了实现没有算错。

### 压力测试

| 场景 | 通关 | 平均差距 | 最大差距 | 说明 |
|---|---|---|---|---|
| 初始蛇长 30 | 100/100 | 1.84 | 40 | 身体真成障碍，避身逻辑有效 |
| 苹果 15 个 | 100/100 | 0.88 | 4 | 但单局极慢（见限制） |

## 高级设置与自动降级

面板底部「高级设置」可以改苹果数和初始蛇长（默认锁定题目规则 10 个 / 3 格）。

**苹果数超过 12 会自动降级。** Held-Karp 是 $O(2^n n^2)$，n=15 时每局约 14 秒，不可接受。所以 `optimalOrder()` 带一个 `maxExact` 参数，超过就走「最近邻 + 2-opt」：

| 苹果数 | 求解方式 | 100 局耗时 |
|---|---|---|
| 10 | Held-Karp（精确） | ~0.4s |
| 12 | Held-Karp（精确） | ~2.5s |
| 15 | 最近邻 + 2-opt | **1.1s**（改成降级前是 14s） |
| 20 | 最近邻 + 2-opt | ~0.6s |

降级后 HUD 里的「理论最优」会**改称「近似值」**，差距栏变「—」，因为此时那个数不再是一个严格下界，拿它算 gap 是自欺欺人。这一点在代码里是显式标记的（`lowerBound()` 返回 `{cost, exact}`），不是靠注释约定。
